# OpenClash 更新中断修复验证（2026-10-22）

## 问题与修复范围

基线：`a5c8c29f6d55876fec069b0d60cccb243c1b37f7`。用户日志为 OpenWrt 25.12.5、`aarch64_generic`、APK，已安装 OpenClash 0.47.156。

`apk update` 报告 `0 unavailable, 2 stale` 并返回非零；原 `maybe_update_index_apk` 没有检查该退出状态，`set -e` 因此在下载插件之前结束脚本。这证明安装流程被提前中断，不能据此断言 OpenClash 包本身不兼容，也不能仅凭这份日志确定网络请求被拒绝的设备侧原因。

修复后：

- 部分或全部索引刷新失败会警告，随后检查已安装依赖并尝试真实安装缺失依赖；依赖事务失败仍立即停止，不伪造成功、不禁用或改写软件源。
- 已安装的 APK 最小依赖不再重复提交安装事务。
- 插件安装后必须从包数据库读到与本次目标发布匹配的版本；缺少版本、仍为旧版本、安装命令失败时都不能输出“完成”。
- 无可用核心或核心下载失败时返回非零，不再额外输出“完成”。
- 交互菜单捕获子任务失败并显示退出码，允许返回菜单；非交互调用保持非零退出状态。空下载脚本被拒绝。

本轮只修改 OpenClash 更新路径和通用菜单错误处理，未重新验证其他六个插件，也未修改 README 或既有 Release。

## 可重复的离线回归

```sh
python3 -m unittest discover -s tests -v
for f in *.sh; do sh -n "$f" || exit; busybox ash -n "$f" || exit; done
shellcheck *.sh
git diff --check
```

20 项回归通过。新用例覆盖部分索引失败后继续、仅安装缺失依赖、依赖失败停止、完整 `main` 入口的真实版本验收、无核心/核心下载失败不得报完成、交互菜单错误处理、非交互失败传播和空脚本拒绝。复现用例在修复前返回 2，修复后通过。

实际伪终端菜单回归也通过：子任务退出 23 后显示错误、回到安装子菜单，再正常退出。

ShellCheck 0.11.0、全部项目 shell 脚本的 POSIX `sh` 与 BusyBox `ash` 语法检查、差异空白检查均通过。

## 固件与多架构验证说明

复用此前从官方固件提取并记录摘要的隔离根文件系统，重新执行当前 OpenClash 安装器。覆盖 OpenWrt 25.12.5 的 35 个 ABI、24.10.8 的 36 个 ABI，以及六个原始 iStoreOS 镜像。APK 路径注入部分索引失败，包安装和核心执行仍由真实包管理器及对应用户态完成。OPKG 路径使用既有索引。

测试缓存保留了此前已下载的固件软件源对象，以便重放相同依赖环境；OpenClash 版本信息和 0.48.002 插件包为本次获取。测试专用下载代理不属于生产脚本。首次复用环境时发现旧代理端口失效，修复测试路由后重新执行；旧失败不作为产品兼容性结论。模拟器 CPU 模型也必须按 ELF ABI 隔离，不能把专用 CPU 设置泄漏到通用辅助程序。

本轮 77 项中，74 项确认插件包为 0.48.002：61 项同时通过核心用户态执行，13 项只计插件安装，3 项测试环境阻塞；没有将未通过/未验证项目计入完整通过。只计插件的项目包括无上游匹配核心的 ARMv4/ARM 大端/PowerPC、Octeon 核心运行失败，以及未确认最低 CPU 指令集的两个 Pentium-MMX ABI。i386 核心在支持 SSE2 的宿主 CPU 上可执行，但低 CPU 模型 QEMU 复核自身崩溃，不能扩大此前的低指令集支持结论。三个阻塞项为 24.10 的 MIPS64 大端、Octeon 和 MIPS64 小端；本轮未重建完整固件内核 VM，不引用此前 VM 结果冒充本轮重测。

逐项结果见 [机器可读矩阵](validation-openclash-update-2026-10-22.json)。`I+C` 表示插件包版本核验和用户态核心版本命令通过；`I` 表示只确认插件包，未确认完整核心兼容；`F` 表示安装失败；`B` 表示验证环境阻塞。除 `I+C` 外均不计完整通过。
